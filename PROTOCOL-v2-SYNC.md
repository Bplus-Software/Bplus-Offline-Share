# B+ Offline Share LAN sync extension2

Additive extension for Android1.0.1 and Windows1.0.1. Existing v1 routes/QR stay unchanged. No internet, encryption or push added. TCP47200 HTTP on trusted LAN only.

POST /sync, Content-Type application/json UTF-8, explicit Content-Length, max48000bytes. Request must have v:2, from:<sender device ID>, senderToken:<sender own token>, targetToken:<receiver token>. Receiver requires an existing paired record for from, matching socket IP and senderToken, plus targetToken equal its local token. Unknown/removed/changed-IP peers fail403. Never log tokens or keys. No /sync data on GET.

Every successful response has v:2, profile:{id,name,username,device} for the receiver (no token/photo), capabilities:["durable-text","receipts","profile"]. Sender must verify returned profile.id equals paired ID before adopting profile or sending queued data. Name is current display/profile name, device is device label. Profile refresh does not change peer ID/token/IP/port.

op:"hello": profile/capabilities only. Sender negotiates this BEFORE auto-retry. Legacy404/unsupported means queue waits for compatible upgrade, not unsafe duplicate-prone fallback.
op:"send": wire and key each64 lowercase hex chars, text nonempty <=8000 Unicode UTF-16 units. Unique stable wire/key generated and durably stored with outbound text before first network attempt. Response additionally wire:<same>, status:"delivered" or "read". Receiver persists message + receipt before ACK. Retrying same sender/wire/key is idempotent, including lost response. Different key collision rejects. ACK is not read. Deleted receipt returns status:"deleted" and sender stops retry, without implying read.
op:"status": items:[{wire,key},...] max100. Response items:[{wire,status},...] with status "unknown", "delivered", "read" or "deleted". Require the correct receipt key; wrong key rejects. Read is persisted only after inbound message appears in the active visible one-to-one conversation, never on ping/notification/list view. It remains read after app restart. Existing tracked files may use the same status query; text queue is the only automatic resend scope.

Queue: persistent outgoing text state queued, sending, delivered, read; sent is a legacy ACK not proof of read. At most one worker per app, retry with same IDs and bounded backoff while service/app operates, resume after restart. Both peers must be reachable on saved LAN addresses, otherwise queue waits. Removal stops pending sends (a request already on the network may still finish) by removing paired trust; preserve local chat/file bytes and show queued text as canceled. Does not remotely erase/revoke other phone. Old local failed text is auto-migrated only when stable valid wire/key exist; untracked old failures stay manual to avoid duplicates. Files/group messages are not auto-retried by this extension.

UI: clock for queued/sending, double gray ticks for delivered, double blue ticks for read, legacy single tick for sent, explicit canceled/failure. Never label a successful ping as delivered/read.
