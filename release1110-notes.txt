B+ Share 1.1.10, device-test pre-release

Private-chat Delete for everyone
- Adds Delete for everyone alongside local chat deletion and, for file selections, Delete files from this phone. Short confirmation explains both phones, receiver's B+ received copy, retained sender originals and irreversibility. Received cards are removed, no placeholder.
- Applies only to newly tracked direct private text/file transfers made using this feature, with both phones on 1.1.10 or newer. Old cards, QR-pulled batch items and groups are not remotely deletable in this version. Unknown items are never matched by filename/size.
- Shared random receipt IDs and per-item capabilities are bound to the exact paired sender/IP/token. Receiver uses its own receipt ledger URI, never any remote-supplied path or URI. Only completed files marked as saved by B+ Share can be erased. Unrelated messages, originals, re-shared copies, other apps' files and other chats are outside the operation.
- Sender removes its card only after the receiver acknowledges deletion. Offline, unsupported, read-only/refused or unknown receipts retain the local card with a not-confirmed label and plain result. Retry is manual. Lost acknowledgements can be retried safely against an idempotent deleted receipt. There is no background queue or promise of delivery while offline.
- Receiver removal targets the exact received card and received file. Sender's own original file remains. If the remote file cannot be deleted, the receiver card also stays and no success is acknowledged. Copies saved/re-shared elsewhere cannot be recalled.
- A successful local permanent file deletion now also removes its selected card(s) from that chat and its library entry. Failures keep selected cards and named reasons. Other chats are not silently cleared.

Emoji panel
- Stays open while inserting multiple emoji. Tap emoji button again, the text field or Back to close. Insertion never sends. Categorized grid/spacing from 1.1.9 retained. Nonmodal panel leaves the composer available.

In-app test updates
- Include test versions setting is ON by default. Updater scans the most recent 100 releases and chooses the highest numeric version, including pre-releases when enabled. Published order does not win over numeric version. GitHub does not expose APK versionCode in release metadata; downloaded package versionCode must still exceed installed versionCode before install, with unchanged package/signature/SHA checks. It never installs a downgrade. Disabling tests selects newer stable releases only.
- Install 1.1.10 manually once from this link; subsequent newer pre-releases can be checked/downloaded/installed inside Settings > Check for updates. No automatic installation.

Validation and limits
- Clean build, versionCode15, original signer. Eleven receipt/auth/ledger assertions cover wrong IP/token/capability/unpaired sender, unknown legacy items, failed byte deletion, ignoring injected request URI, exact card removal, idempotent retry and text never invoking byte deletion. Prior gesture, record/deletion path, sharing/group/nearby/message/updater suites pass; exact released 1.1.9 downloader candidate redirect/hash test included.
- This is a new protocol, NOT verified between two physical Android phones. Android 1.1.10 pixels, emoji panel touch/back/keyboard positioning, remote/local file permissions and actual transfer/recall remain unverified. Risk unmeasured. First test with disposable new text and small file on two updated phones, including an offline attempt and retry. No promotion based on code tests alone.
- Local trusted Wi-Fi/unencrypted HTTP limits remain. A token/IP/capability gate is not end-to-end encryption or protection against a compromised paired phone/LAN observer. IP changes can require re-pairing. No groups recall, offline queue, cloud relay, Windows, old-file matching or general deleted-file recovery.
- Voice messages are planned separately for 1.1.11, not included here.
- Pre-release, 1.1.5 stays GitHub normal latest. Install 1.1.10 manually over the current app once, without uninstalling. Downgrade can require uninstalling and lose local chats/settings. System prompts/pickers keep Android UI.
